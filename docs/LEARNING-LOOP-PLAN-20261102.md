# 推荐学习闭环实施计划

更新日期：2026-11-02。本文是现状记录和待实施计划，不代表下述开发已完成。本轮仅新增本文档，不修改程序、数据库、定时任务或服务器配置。

## 目标与边界

实现原则：遵循根目录 AGENTS.md，避免过度防御。优先复用现有入口，以最少必要改动解决已证实的问题；不为假设中的极端异常新增多级兜底、重复校验或通用框架。下文的预算、幂等和数据边界优先使用现有机制，不要求层层重复实现。

建立“保存候选 → 跟踪结果 → 评估反馈 → 对照验证 → 有证据后调整”的闭环。不能承诺推荐次数越多就必然越准。保留原评分作为基线；不使用今日行情生成历史信号，不把观察样本收益等同于可成交收益。

## 阶段一：保证评价数据可靠

### P0：自动 T+3 补齐

- 找出已成熟且覆盖不足的信号日，解析每个日期的真实 T+3 交易日。
- 在现有 maturity backfill 前调用现有行情补齐，目标为对应 T+3 日期，而非 T+1 日期。
- 整批共享预算，避免每个日期单独占满预算；沿用锁和幂等机制。失败记录日期、缺失数、原因并允许下次恢复。
- 预算耗尽或上游不可用时保留有效数据，不填零、不提前标记评价成功。
- 修复后按现有顺序刷新策略反馈、场景反馈、纠偏效果和 ML 样本。

验收：T+1 完整但 T+3 缺失的用例能自动补齐；未成熟日期不评价；重复运行不改变信号和 T+1；接口失败、预算耗尽均有明确状态；服务器选定日期复核达到覆盖门槛。

### P0：板块采集及映射状态

- 用少量请求比较同一接口在本机和服务器的响应，不进行大量重试。
- 若现有端点仍不可用，评估替代源的板块定义、代码映射、字段单位和日期一致性；未完成验证不混用。
- 修复映射任务上游失败却显示“失败 0”的误导性汇总，保留旧映射并标明过期。
- 数据不足继续 partial，暂停新增推荐；不能直接改发布标志掩盖问题。

验收：有效数据才能报告刷新成功，错误返回明确失败；空响应不能清空旧映射；行业和概念均完整且日期正确才能解除相关降级。

### P1：历史缺口和定时运行

- 独立核验交易日历，再检查已有数据库数据和可用备份。无同日信号或快照的日期保留缺口，不混入真实历史推荐评价。
- 验证 20:15、21:00、23:00 的运行状态、锁释放、发布日期和邮件跳过。已有当日报告时幂等跳过是正常，但必须另验下一交易日自动生成。

## 阶段二：建立能解释的固定对照

- 同一日期、同一候选全集同时冻结原规则结果和纠偏结果，记录信号身份、规则版本、反馈截止时间和降级原因。
- 将原始候选表现、过滤效果、组合可交易表现分开，不将不同股票组的简单收益差解释为因果收益。
- 按股票与日期去重，避免同股多策略放大样本；报告独立交易日数、覆盖率和缺失情况。
- 对照保持相同持有期、选取数量及可交易约束；组合评估需明确成交时点、涨跌停/停牌、交易成本和滑点假设。
- 反馈只能使用推荐时已经成熟并可获得的标签。历史验证禁止读取“当前最新反馈”冒充历史可用反馈。
- 同时报告胜率、平均收益、下行损失、换手、样本量与不确定性；保留组为空时明确不可比较，不填造净收益。

验收：固定输入可复现；未来标签无法影响过去推荐；重复策略不会增加股票样本数；无对照、覆盖不足、样本不足时不输出有效性结论。

## 阶段三：模型旁路实验

- 基于已验证的数据集做轻量模型实验，不改变正式排序。1730 行不是 1730 个独立市场样本，不能仅凭行数宣布足够。
- 按日期划分训练、验证和最终测试，使用滚动时间验证；同一天的样本不能随机分散到训练和测试。
- 标签窗口重叠处设置隔离，特征仅采用推荐时快照；预处理和缺失值参数只从训练段学习。
- 与固定原规则和现有纠偏分别比较，保存数据版本、特征清单、时间切分、模型版本及旁路输出。
- 实验阈值、主要指标、最低独立日期数和成本假设在看测试结果前确定。最终测试集不得反复调参使用。

验收：样本外结果可复现，无明显时间泄漏；劣化场景可解释；无证据提升则保留原排序。

## 阶段四：满足条件后有限接入

只有跨多个时间窗口的样本外结果和实际旁路运行均支持改进，才讨论小权重接入。接入前明确版本、权重上限、停用条件和一键回退；保留原基线并持续对照。模型异常或数据质量不足自动退回原规则。自动训练不等于自动晋升生产。
