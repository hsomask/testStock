## 结论

检查点 C 本地代码验收通过。改动收敛外部数据源边界、K 线残缺目标日刷新、来源追溯及受控失败；未修改选股公式、评分、排序、阈值、策略层或涨停口径。服务器最终版本全链路运行仍属于部署验收，不在本地代码验收结论内。

## C1：K 线 Provider 等价提取

- 保留 `analysis.data_fetcher` 中原有兼容函数名和调用顺序。
- Sina 仍为主通道，Tencent 仍为失败后的备用通道。
- 请求参数、15 秒超时、字段归一化、空数据和异常降级与旧实现一致。
- 真实接口验证：Sina 返回 5 行，Tencent 返回 6 行；字段满足既有 OHLCV 契约。

## C2：目标日期刷新、来源追溯和冲突检查

- 完整目标交易日继续直接使用数据库缓存。
- 目标交易日缺失或 OHLCV 残缺时强制请求 API。
- 仅允许 API 替换残缺目标日；已有完整历史行保持数据库优先，避免意外重写历史。
- 新写入 K 线明确记录 `sina` 或 `tencent`，不再使用笼统的 `get_stock_history`。
- 同日期完整 OHLCV 有差异时记录冲突告警，不自动覆盖完整缓存。
- API 未返回待刷新目标日时保留数据库旧行，不再误删该日；同时记录未完成刷新告警。

## C3：涨停生态与板块映射 Provider

- 涨停生态继续调用统一全市场快照，不再增加一层无价值转发。
- 数据源统一放入既有 `analysis/data_sources`，不再并存 `providers` 目录。
- 全市场、板块行情和板块映射共用唯一 EastMoney 分页客户端。
- 分页增加单页重试、最大页数和连续空页熔断，不返回不完整的静默部分数据。
- EastMoney 预检成功但正式取数失败时，全市场快照会降级到 Sina。
- 主源和备用源均须满足核心字段与至少 1000 只股票的质量门槛，残缺股票池不会进入选股。
- 板块映射接口失败时保留旧映射，并继续沿用原有逐板块事务隔离；整体或局部失败最终返回非零状态，避免 cron 误报成功。
- 真实接口验证：全市场快照 5538 只，来源为 EastMoney；行业板块 496 个，抽样板块成分股有效。
